# Documentation

Your database documentation lives here, or is linked from here if you host it
on dbdocs.io or GitHub Pages.

It should list, for every table: each feature's name, its data type, whether
it's a primary or foreign key, and a short note saying what the feature
*means* — not what it's called. `member_id — the member id` is not a note.

Include an ER diagram showing the relationship between your tables.
